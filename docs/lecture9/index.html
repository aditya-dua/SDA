03 / 09Concept

One Collection Is Not Enough

In L8 every stock price went into sda_course.stock_prices. That is exactly right for a data analyst querying trends — but a portfolio manager only wants to see the moments that matter.

UserWhat They NeedHow Often They Check
BI / Data AnalystAll prices, full historyBatch queries, once a day
Portfolio Manager / RiskOnly significant movesEvery few minutes — or instantly

Forcing both users into the same collection means the risk user must filter thousands of normal ticks every time to find the 8 that matter.

Business Analogy: stock_prices is a complete call recording library. stock_alerts is the auto-flagged escalations queue. Both exist. Different people action them.

05 / 09Concept

Alert Rules: Stateless vs Stateful

All alert logic is an if statement — the question is whether it evaluates one message alone, or needs to remember previous messages.

Stateless — no memory needed
📉 Price Below Floor
INFY < ₹1,400 → ALERT
TCS < ₹3,200 → ALERT

Each message evaluated alone. No history required.

Stateful — remembers last price
⚡ Rapid Move > 1.5%
|Δ from prev price| > 1.5% → ALERT

Remembers previous price per symbol in a Python dict.

python — stateful in-memory state
last_price = {}   # {"INFY": 1423.50, "TCS": 3541.00, ...}

def check_rapid_move(symbol, price):
    if symbol in last_price:
        pct = (price - last_price[symbol]) / last_price[symbol] * 100
        if abs(pct) > 1.5:
            return f"RAPID_MOVE:{pct:+.2f}%"
    last_price[symbol] = price
    return None

Note: last_price lives in RAM. A consumer restart loses it until the second message per symbol. Module 3 covers durable state for production.

06 / 09Lab

consumer_alerts.py — Full Code

python · consumer_alerts.py
from kafka import KafkaConsumer
from pymongo import MongoClient
from datetime import datetime
import json

MONGO_URI  = "mongodb+srv://<user>:<pass>@cluster0.xxxxx.mongodb.net/"
client     = MongoClient(MONGO_URI)
db         = client["sda_course"]
prices_col = db["stock_prices"]   # same as L8
alerts_col = db["stock_alerts"]   # new collection — auto-created

last_price   = {}
PRICE_FLOORS = {"INFY": 1400, "TCS": 3200}

def get_alerts(symbol, price):
    reasons = []
    if symbol in PRICE_FLOORS and price < PRICE_FLOORS[symbol]:
        reasons.append(f"BELOW_FLOOR:{symbol}<{PRICE_FLOORS[symbol]}")
    if symbol in last_price:
        pct = (price - last_price[symbol]) / last_price[symbol] * 100
        if abs(pct) > 1.5:
            reasons.append(f"RAPID_MOVE:{pct:+.2f}%")
    last_price[symbol] = price
    return reasons

consumer = KafkaConsumer(
    'stock-topic', bootstrap_servers=['localhost:9092'],
    auto_offset_reset='latest',
    value_deserializer=lambda x: json.loads(x.decode('utf-8'))
)
print("📡 Listening on stock-topic (Ctrl+C to stop)...")

for msg in consumer:
    data   = msg.value
    symbol = data.get('symbol', '?')
    price  = float(data.get('price', data.get('Close', 0)))

    # Step 1 — save every message (same as L8)
    prices_col.insert_one({**data, '_saved_at': datetime.utcnow()})
    # Step 2 — evaluate and route alerts
    reasons = get_alerts(symbol, price)
    if reasons:
        alerts_col.insert_one({
            'symbol': symbol, 'price': price,
            'alert_reasons': reasons,
            'alert_at': datetime.utcnow(), 'status': 'open'
        })
        print(f"🚨 [{symbol}] ₹{price} → {', '.join(reasons)}")
    else:
        print(f"💾 [{symbol}] ₹{price}")

09 / 09Wrap-Up

Key Takeaways

  • ✓One Kafka topic → multiple collections via a single consumer — no extra producers needed
  • ✓Stateless rules evaluate one message alone; stateful rules need in-memory state per symbol
  • ✓The two-collection pattern serves different business users without duplicating infrastructure
  • ✓status: "open" in alert docs gives your risk team a structured, queryable action queue
  • ✓Both collections are ready for Atlas Charts in Module 4 — dashboards on data you already have
