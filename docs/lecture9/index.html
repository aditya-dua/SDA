03 / 09 Framework

4 Things You Can Do With Streaming Data

Every real-world streaming consumer does one or more of these. Decide before you write a line of code.

💾 Store
Persist every message to a database
MongoDB, PostgreSQL, S3 — enables batch analysis later
📊 Aggregate
Compute running totals, averages, counts
Revenue per minute, average price last 10 ticks, top 5 movers
🔔 Trigger
Fire an action when a threshold is crossed
Price drops 5% → send alert; order > ₹10L → flag for review
✨ Enrich
Join stream with reference data in real time
Add company name to ticker, convert currency, classify transaction

MBA lens: What question does your manager need answered in the next 60 seconds? That question determines which action(s) your consumer performs.

04 / 09 Concept

Where Do You Start Reading?

The auto_offset_reset setting is a business decision, not just a config option.

SettingBehaviourUse When
earliest Read ALL messages from the very first one ever stored Building a historical report, backfilling a database, first-time setup
latest Ignore old messages — only read what arrives from now on Live dashboard, real-time alert, anything that only cares about "right now"

Analogy: earliest = reading a book from page 1. latest = walking into a conversation already in progress and only listening from now.

Important: Once a consumer has read a message, its offset is committed. If the consumer restarts it resumes from the last committed offset — not from earliest or latest again.

05 / 09 Lab — Level 2

Python Consumer — Analytics

Running totals per symbol — see TCS and INFY stats update with every new message.

python · consumer_analytics.py
from kafka import KafkaConsumer
import json
from collections import defaultdict

consumer = KafkaConsumer(
    'stock-topic',
    bootstrap_servers=['localhost:9092'],
    auto_offset_reset='earliest',
    value_deserializer=lambda x: json.loads(x.decode('utf-8'))
)

totals = defaultdict(lambda: {'count': 0, 'sum': 0.0, 'min': float('inf'), 'max': 0.0})

for msg in consumer:
    data  = msg.value
    sym   = data.get('symbol', '?')
    price = float(data.get('price', data.get('Close', 0)))

    s = totals[sym]
    s['count'] += 1
    s['sum']   += price
    s['min']    = min(s['min'], price)
    s['max']    = max(s['max'], price)
    avg           = s['sum'] / s['count']

    print(f"[{sym}]  price=₹{price:.2f}  avg=₹{avg:.2f}  min=₹{s['min']:.2f}  max=₹{s['max']:.2f}  n={s['count']}")
06 / 09 Lab — Level 3

Python Consumer — Triggers & Alerts

Fire an alert when a stock price drops more than a set threshold from the previous tick.

python · consumer_alerts.py
from kafka import KafkaConsumer
import json

consumer = KafkaConsumer(
    'stock-topic',
    bootstrap_servers=['localhost:9092'],
    auto_offset_reset='earliest',
    value_deserializer=lambda x: json.loads(x.decode('utf-8'))
)

ALERT_THRESHOLD = 2.0   # alert if price drops more than 2%
prev = {}                 # last price per symbol

for msg in consumer:
    data  = msg.value
    sym   = data.get('symbol', '?')
    price = float(data.get('price', data.get('Close', 0)))

    if sym in prev:
        change_pct = ((price - prev[sym]) / prev[sym]) * 100
        if change_pct <= -ALERT_THRESHOLD:
            print(f"🚨 ALERT  {sym}  ₹{prev[sym]:.2f} → ₹{price:.2f}  ({change_pct:.2f}%)")
        else:
            print(f"   OK     {sym}  ₹{price:.2f}  ({change_pct:+.2f}%)")

    prev[sym] = price

Challenge: Change ALERT_THRESHOLD to 1.0 and run with btc_producer.py (from Lecture 6). How often does BTC trigger your alert?

09 / 09 Wrap-Up

Module 2 Complete — Key Takeaways

  • Every consumer makes one of 4 decisions: Store · Aggregate · Trigger · Enrich
  • earliest = historical replay; latest = live-only — choose based on the business question
  • Analytics consumer tracks running stats per symbol with zero external tools
  • Alert consumer fires on threshold crossings — the simplest form of real-time monitoring
  • One topic, many consumers — analytics and alerts run independently on the same stream
