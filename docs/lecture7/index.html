04 / 12 Theory

Where We Are

Lecture 6 built the sender. Today we build the receiver.

producer.py
"an event happened"
→→→
Kafka Topic
durable inbox
→→→
consumer.py
"now what?" ← YOU ARE HERE

Kafka holds every message even after it's read. Consumers can:

  • Re-read old messages — replay history
  • Start reading from any point in time
  • Process at their own pace, independent of the producer

The shift: From reporting on what happened to responding as it happens.

05 / 12 Framework

4 Things You Can Do With Streaming Data

Every consumer does one or more of these:

Store
Save the raw event to a database
→ Audit log, order history, compliance record
Aggregate
Count, sum, average over time
→ Revenue per hour, items sold per minute
Trigger
Fire an action when a condition is met
→ Alert if order > $1,000, flag suspicious login
Enrich
Add context from another data source
→ Attach customer tier, lookup product margin

Key insight: The same event stream can power all four simultaneously — each consumer serves a different business need.

06 / 12 Decision

Where Do You Start Reading?

When a consumer connects to a topic, it must decide: start from the beginning or only from now?

SettingBehaviourUse When
earliest Read every message from the start of the topic Analytics backfill, reconciliation, you need history
latest Only read new messages arriving after now Fraud alerts, live dashboards — only the present matters

This is a business decision, not a technical one.
Ask: "Does my use case require the past, or only the present?"

The Offset — Your Bookmark

Kafka tracks where each consumer stopped using a number: the offset. If your consumer crashes and restarts, it resumes exactly where it left off. Think of a podcast app that remembers your position.

07 / 12 Demo

Kafka Console Consumer

Before writing Python — verify your stream is live with zero code.

Read all messages from the beginning

bash
docker exec -it kafka kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic orders-topic \
  --from-beginning

Read with metadata (offset + timestamp)

bash
docker exec -it kafka kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic orders-topic --from-beginning \
  --property print.offset=true \
  --property print.timestamp=true

When to use the console: Debugging — "Is data actually in this topic?" Verify before writing a single line of Python.

08 / 12 Lab — Level 1

Python Consumer — Basic

Read and print every message. Verify the pipeline end-to-end.

python · consumer_basic.py
from kafka import KafkaConsumer
import json

consumer = KafkaConsumer(
    'orders-topic',
    bootstrap_servers=['localhost:9092'],
    auto_offset_reset='earliest',   # 'latest' for new messages only
    value_deserializer=lambda x: json.loads(x.decode('utf-8'))
)

for message in consumer:
    order = message.value
    print(f"[Offset {message.offset}]  "
          f"Order: {order.get('order_id')} | "
          f"Product: {order.get('product')} | "
          f"Amount: ${order.get('amount', 0):.2f}")

Run producer.py in one terminal and this in another — watch events appear live.

09 / 12 Lab — Level 2

Python Consumer — Analytics

Running totals, top products, top spenders — updated live every 5 orders.

python · consumer_analytics.py
from kafka import KafkaConsumer
import json, time

consumer = KafkaConsumer('orders-topic',
    bootstrap_servers=['localhost:9092'],
    auto_offset_reset='earliest',
    value_deserializer=lambda x: json.loads(x.decode('utf-8')))

total_orders, total_revenue = 0, 0.0
product_counts, user_spending = {}, {}
start_time = time.time()

for message in consumer:
    order = message.value
    total_orders  += 1
    total_revenue += order.get('amount', 0)
    product = order.get('product', 'Unknown')
    product_counts[product] = product_counts.get(product, 0) + 1

    if total_orders % 5 == 0:
        top = max(product_counts, key=product_counts.get)
        print(f"Revenue: ${total_revenue:,.2f} | "
              f"Top product: {top}")

This is analytics, not just data collection. The consumer is surfacing a business signal in real time.

10 / 12 Lab — Level 3

Python Consumer — Triggers & Alerts

Fire an action the moment a condition is met in the stream.

python · consumer_alerts.py
from kafka import KafkaConsumer
import json

consumer = KafkaConsumer('orders-topic',
    bootstrap_servers=['localhost:9092'],
    auto_offset_reset='latest',  # only NEW orders from now
    value_deserializer=lambda x: json.loads(x.decode('utf-8')))

HIGH_VALUE = 1000.00
WATCH_LIST = ["Laptop Pro", "4K Monitor"]

for message in consumer:
    order   = message.value
    amount  = order.get('amount', 0)
    product = order.get('product', '')

    if amount >= HIGH_VALUE:
        print(f"🔔 HIGH VALUE: {order['user_id']} spent ${amount:.2f}")

    if product in WATCH_LIST:
        print(f"📌 WATCHED: {product} sold → {order['user_id']}")

12 / 12 Wrap-Up

Key Takeaways

  • The console consumer is your debugger — use it before writing any Python
  • earliest vs latest is a business decision — do you need the past or just now?
  • The offset is your bookmark — consumers resume exactly where they left off
  • Four actions: Store · Aggregate · Trigger · Enrich — every consumer does one or more
  • One stream, many consumers — fraud, analytics, alerts, storage all run independently
